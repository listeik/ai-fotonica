# Воспроизведение сравнения

После установки backend и обучения модели запустите из корня проекта:

```shell
python -m doe.benchmark --checkpoint artifacts/doe-unet.pt --device cpu --samples 16 --output experiments/comparison
```

По умолчанию сравниваются классический Adam с бюджетами 20 и 200 шагов, один проход U-Net и гибрид с 20 шагами Adam. Последний начинает с фазы сети. У Adam один старт и шаг обучения 0.08. Бюджеты задаются флагами `--classical-steps` и `--hybrid-steps`. Если опустить `--checkpoint`, будет измерен только классический метод. Для CUDA укажите `--device cuda`. При сравнении времени используйте одно устройство и одинаковое число потоков `--threads`.

Каждый метод получает одни и те же четыре цели из отдельной синтетической выборки. Параметры генератора и начальное состояние оптимизатора записываются в JSON. Прогрев использует выборку `demo`. Для подбора настроек используйте `--split val` и сохраните итоговую оценку на `test` для выбранной конфигурации.

Время синтеза измеряется после загрузки весов и прогрева и не включает построение PNG или расчёт метрик. Восстановление выполняется из декодированного фазового PNG. Модуль поля каждой плоскости делится на максимум этой плоскости и округляется до 8 бит. PCC равен нулю при постоянном целевом или восстановленном изображении. SSIM рассчитан с окном 7×7 и диапазоном данных [0, 1].

- `comparison.csv` содержит одну строку на сочетание набора целей и метода с показателями четырёх плоскостей.
- `comparison.json` сохраняет те же показатели, агрегаты, хеши целей и фазовых PNG, хеш весов, версии библиотек и время загрузки модели.
- `report.md` и `comparison.png` показывают средние и худшие значения метрик, а также медианное время синтеза. Худшее значение — минимум по всем плоскостям всех наборов.

Синтетические цели проверяют обобщение в пределах описанного генератора. Проверка на изображениях другого происхождения требует отдельного набора и того же протокола оценки.
