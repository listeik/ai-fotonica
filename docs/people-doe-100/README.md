# Сто наборов фотографий людей с фазовыми ДОЭ

Данные находятся в `runs/people-doe-100-v1/`. Сто наборов содержат 400 целей, 100 общих для четырёх плоскостей ДОЭ и 400 восстановлений. В каждом наборе четыре портрета разных людей. Все основные изображения являются одноканальными 8-битными PNG 128×128. Архив всего набора находится в `runs/people-doe-100-v1.zip`.

Цели зафиксированы до оптимизации ДОЭ. Фотографии сохраняют исходные уровни серого и увеличены с 64×64 до 128×128 фильтром Lanczos. Четыре разные фотографии действительно подаются на вход обратной задачи. Метрики каждого набора показывают полученное качество, включая результаты ниже 0,8. Пользователь выбрал подготовку всех 100 наборов с лучшими найденными решениями и фактическими метриками.

Использована MATLAB-версия Olivetti Faces, которую распространяет scikit-learn. В ней 400 разных кадров 40 людей, по десять кадров на человека. Оригинальная коллекция AT&T/ORL включает варианты выражения лица, позы, освещения и очков. При использовании изображений нужно указать AT&T Laboratories Cambridge. Контрольная сумма архива сверена с кодом scikit-learn. [Описание AT&T](https://cam-orl.co.uk/facedatabase.html/) · [Описание версии 64×64](https://sklearn.org/stable/modules/generated/sklearn.datasets.fetch_olivetti_faces.html) · [Официальный загрузчик с SHA-256](https://raw.githubusercontent.com/scikit-learn/scikit-learn/main/sklearn/datasets/_olivetti_faces.py)

Каждый исходный кадр использован ровно один раз. Все десять кадров одного человека принадлежат одной выборке. Внутри набора четыре разных исходных человека. Это портретная коллекция с ограниченным числом людей и фонов. Она дополняет широкий датасет целей отдельной задачей на лица.

## Структура

Каталоги имеют вид `<split>/<set:03d>/`. Файлы `target-1.png`–`target-4.png` являются входными целями для расстояний 24,1, 25,3, 26,5 и 27,7 мм соответственно. `doe.png` содержит общую фазу. `reconstruction-1.png`–`reconstruction-4.png` восстановлены непосредственно из этого PNG. `result.json` хранит метрики каждой плоскости, историю контрольных точек, выбранные итерацию и старт, время расчёта и SHA-256 всех девяти PNG.

Корневой `manifest.json` фиксирует происхождение каждой цели, идентификатор человека в исходной коллекции, номер кадра, split, параметры поиска, физические параметры и версии библиотек. Корневой `summary.json` содержит распределение метрик, число наборов, прошедших пороги 0,8 и 0,9 одновременно по PCC и глобальному SSIM на всех четырёх плоскостях, и результаты всех ста наборов. `preview.png` показывает исходные фотографии и восстановления для пяти наборов на разных уровнях качества. Копии манифеста и сводки находятся в этом каталоге документации.

## Поиск и проверка

Для каждого набора выполнены два запуска Adam по 2000 итераций с начальным шагом 0,04 и косинусным снижением до 0,001. Первый запуск предваряют 160 итераций многоплоскостного Gerchberg–Saxton, второй начинается со случайной фазы. Фаза квантуется до экспортных уровней с прямой передачей градиента. Целевая функция учитывает средний и худший PCC и глобальный SSIM. Каждые 100 шагов кандидат экспортируется в PNG, читается заново и оценивается. Выбирается кандидат с максимальным минимумом восьми значений PCC и глобального SSIM. При равенстве сравнивается сумма средних PCC и SSIM. Это лучшее найденное решение в рамках указанного поиска. Доказательство глобального оптимума отсутствует.

Расчёт использует существующую модель проекта. Длина волны 532 нм, шаг ДОЭ 10 мкм, равномерная плоская волна, фазовая апертура 128×128. Фаза декодируется по формуле `φ = code × 2π / 255 − π`. Восстановление нормирует `abs(U)` каждой плоскости на её максимум и округляет до 8 бит. В отчётах PCC и глобальный SSIM считаются по этим пикселям. Дополнительно сохранён локальный SSIM с окном 7×7 и MSE.

Команда проверки перечитывает все 900 PNG, проверяет формат, контрольные суммы, отсутствие повторов целей и исходных кадров, четыре разных человека на набор, разделение людей между выборками и повторяет физическое восстановление каждой ДОЭ с пересчётом всех метрик.

## Попытка повысить метрики выше 0,9

Порог одновременно по PCC и глобальному SSIM на всех четырёх плоскостях не достигнут ни в одном из 100 наборов. Число наборов, прошедших аналогичный порог 0,8, тоже равно нулю. Медиана по ста наборам для среднего по четырём плоскостям PCC составляет 0,6884, глобального SSIM — 0,6484. Эти решения позволяют изучать реальные ограничения обратной задачи; они не являются высокоточными эталонами с гарантией 0,9.

Дополнительный поиск выполнялся на двух наборах из `train`. Для `train/023` проверены 4000 шагов Adam с оптимизацией PCC по ненормированной амплитуде, затем L-BFGS с двух начальных фаз: исходной и полученной после Adam. Каждый запуск L-BFGS включал 30 блоков до 20 внутренних итераций с поиском шага strong Wolfe. Отдельный средний PCC достигал 0,7749, но одновременно ухудшался SSIM. По критерию минимума всех восьми метрик исходная ДОЭ осталась лучше.

Для `train/048` выполнены ещё 12 000 шагов Adam с начальным шагом 0,012, снижением до 0,0002 и балансировкой худших плоскостей гладким минимумом. Этот вариант улучшил совместный критерий и включён в датасет:

| Метрика для `train/048` | До уточнения | После |
| --- | ---: | ---: |
| Средний PCC | 0,7464 | 0,7613 |
| Худший PCC | 0,7455 | 0,7527 |
| Средний глобальный SSIM | 0,7228 | 0,7384 |
| Худший глобальный SSIM | 0,7170 | 0,7327 |
| Средний локальный SSIM, окно 7×7 | 0,2833 | 0,3038 |
| Худший локальный SSIM, окно 7×7 | 0,2494 | 0,2682 |

Полная история этих попыток, метрики до и после и контрольные суммы входов находятся в `quality-search.json`. Значения локального и глобального SSIM существенно различаются, поэтому они явно подписаны. Фотографии при уточнении оставались фиксированными. После замены ДОЭ все 100 наборов прошли повторную проверку с пересчётом восстановления из сохранённой фазы. Время дополнительных запусков не регистрировалось; поле `seconds` в результатах отражает исходный поиск.

Скрипт `backend/scripts/refine_people_doe.py` повторяет дополнительные методы. Входной каталог должен содержать четыре цели и исходную `doe.png`, выходной каталог должен быть новым:

```powershell
.venv/Scripts/python.exe backend/scripts/refine_people_doe.py runs/people-doe-100-v1/train/048 runs/people-refinement-new --method balanced --apply
```

Без `--apply` сохраняются только отдельные кандидаты. С `--apply` скрипт заменяет исходную ДОЭ лишь при улучшении совместного критерия и обновляет `result.json`. Для новой корневой сводки после самостоятельного уточнения нужно вызвать `verify(output)` и `preview(output, summary["results"])` из `prepare_people_doe.py` и сохранить результат проверки как `summary.json`. Метод `mixed` запускает вариант с PCC и двумя L-BFGS. Применение команды к уже уточнённой ДОЭ начинает новый поиск с текущей фазы и не обязано повторить цифры первого уточнения.

В локальном архиве также сохранены исходный MAT-файл и снимок численного кода в `reproduce/` с SHA-256 в манифесте. Проверка снимком не зависит от последующих изменений рабочих файлов проекта:

```powershell
.venv/Scripts/python.exe runs/people-doe-100-v1/reproduce/prepare_people_doe.py verify --output runs/people-doe-100-v1
```

Модуль `backend/scripts/people_doe_reference.py` явно фиксирует формулы PCC и глобального SSIM для этого датасета. Его значения и градиенты по фазе проверены на точное совпадение с реализацией, использованной при расчёте. Все 100 сохранённых результатов повторно проверены через этот модуль. Дополнительно проверено отклонение повреждённой цели и манифеста с пересечением людей между выборками.

```powershell
.venv/Scripts/python.exe backend/scripts/prepare_people_doe.py build
.venv/Scripts/python.exe backend/scripts/prepare_people_doe.py verify
.venv/Scripts/python.exe backend/scripts/prepare_people_doe.py package
```

Сборка поддерживает продолжение с теми же `--seed`, `--steps` и `--restarts`, пропуская завершённые наборы. По умолчанию используются четыре вычислительных процесса по одному потоку PyTorch. Для новой сборки задайте новый `--output`. Полный массив PNG хранится локально в исключённом из Git каталоге `runs/`.
