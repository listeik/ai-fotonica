# Smart DOE Optimization

После обычного Neural-синтеза кнопка «Улучшить качество» открывает панель поиска. Исходные цели сохраняются в текущей сессии. Пользователь выбирает режим, запускает поиск, просматривает все варианты и принимает выбранный ДОЭ отдельной кнопкой. При отмене или ошибке исходный результат остаётся доступным.

## Оценка и выбор

Baseline восстанавливается заново из переданного фазового PNG. Каждому следующему кандидату соответствует один вызов текущей сети. Поддерживаются коррекция контраста по перцентилям, гамма, яркость, мягкий медианный фильтр, ограниченное подавление высоких частот и три фиксированные комбинации. Порядок вариантов определяется яркостью, контрастом и высокочастотной энергией целей. Все входы округляются до 8-битных уровней.

Каждый ДОЭ экспортируется существующим методом синтеза. Официальные PCC и Global SSIM пересчитываются по реконструкциям этого PNG относительно исходных четырёх изображений. Порядок плоскостей сохраняется. Windowed SSIM использует Gaussian 11×11, sigma 1.5, population moments и внутреннюю область изображения. Фоновая мощность считается через общий диагностический модуль по интенсивности до нормировки, для пикселей цели с яркостью ≤2/255.

Score равен среднему четырёх величин — mean PCC, mean Global SSIM, worst PCC и worst Global SSIM. Кандидат допускается только при выполнении всех условий.

- Средние PCC и Global SSIM не ниже baseline с учётом mean tolerance.
- PCC и Global SSIM каждой плоскости, а также худшие показатели не ниже baseline более чем на plane tolerance.
- Score превышает score baseline более чем на minimum gain.

Из допустимых кандидатов выбирается максимальный score. Пороги задаются через окружение backend.

| Переменная | Значение по умолчанию | Значение |
|---|---:|---|
| DOE_SMART_MAX_CANDIDATES | 16 | Бюджет, включая baseline, от 2 до 20 |
| DOE_SMART_PLANE_TOLERANCE | 0.002 | Допустимое абсолютное снижение по плоскости |
| DOE_SMART_MEAN_TOLERANCE | 0 | Допустимое абсолютное снижение среднего |
| DOE_SMART_MINIMUM_GAIN | 0.0005 | Минимальный прирост score |

Оба режима выбирают ДОЭ по оригинальным целям. В режиме «Сохранить оригиналы» принятие меняет только результат. В режиме «Адаптировать изображения» принятие также заменяет рабочие цели. В паспорте такого результата хранятся метрики относительно оригиналов и адаптированных целей, обе версии изображений и конфигурация преобразований.

## API и жизненный цикл

POST /api/smart принимает multipart с четырьмя images, phase от обычного Neural-синтеза, model_version, baseline_seconds и mode со значением preserve или adapt. Возвращает HTTP 202 и идентификатор. Baseline seconds сохраняет время предыдущего запуска, поступившее от клиента. Все метрики сервер рассчитывает заново.

GET /api/smart/{id} возвращает состояние и число проверенных вариантов. GET /api/smart/{id}/result возвращает полный отчёт после завершения, отмены или ошибки. GET /api/smart/{id}/candidates/{index} возвращает рассчитанный вариант, включая подготовленные изображения. POST /api/smart/{id}/cancel запрашивает отмену после текущей операции.

Задача исполняется вне HTTP-запроса в потоке через asyncio и существующий thread pool. Один общий слот защищает сеть и физическую модель от одновременного обычного синтеза и поиска. Отмена сохраняет слот до фактического завершения текущей операции. Ошибка также освобождает слот. При завершении сервера задачи получают отмену.

Реестр работает в одном процессе backend. Завершённые отчёты живут до 15 минут, сохраняются максимум три завершённые задачи. После перезапуска сервер очищает реестр. Временные файлы на диск не создаются. Для нескольких workers потребуется общий реестр и очередь. Текущий Docker запускает один worker.

Поиск возвращает число дополнительных Neural-запусков и общее время работы отдельно от времени синтеза выбранного ДОЭ. Принятый результат помечается Smart в таблице и паспорте. Для конкурсного протокола с одним forward используется обычный Neural-синтез.

## Проверка

Тесты покрывают квантование и оценку по оригиналам, воспроизводимость преобразований, согласование плоскостей, отсутствие улучшения, запрет снижения отдельных метрик, валидацию checkpoint, совместный лимит, отмену, перезапуск задачи и освобождение слота при ошибке.

Проверка Docker API на Carrier checkpoint d4176bb99d8c прошла на пяти квартетах с бюджетом 16 кандидатов. Для каждого кандидата официальные метрики независимо пересчитаны по оригиналам. Фотографии взяты из локального тестового квартета Olivetti. Остальные цели включают процедурную геометрию, символы, контуры, случайную текстуру с seed 20261108 и смешанный квартет из этих источников.
